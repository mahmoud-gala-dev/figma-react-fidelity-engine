# المقترح الفني: منصة فحص تطابق تصميم Figma مع تنفيذ React

## الملخص التنفيذي
منصة اختبار بصري وبنيوي تساعد فرق تطوير الواجهات على قياس مدى التزام مكونات React بالمواصفات المسجلة في تصميمات Figma. يجمع النظام بيانات التصميم في صيغة موحدة، ويفحص الواجهة الفعلية في متصفح Chromium، ويكتشف الفروق القابلة للقياس، ويولد تقارير HTML للعميل والإدارة.

## المشكلة التي تعالجها
عادةً تتم مراجعة التصميم يدويًا عبر النظر إلى الشاشات؛ فيصعب اكتشاف الانحرافات الصغيرة أو توثيق كل فرق بصورة يمكن إعادة إنتاجها. يتيح MVP تجربة تدقيقية تشرح ما قورِن تحديدًا، وأين وقع الانحراف، وما الأدلة المستخدمة.

## نطاق المشروع
- استيراد مواصفات عنصر من ملف JSON مرفق، أو ملف `.fig` محلي (مع تحقق)، أو ملف ZIP من إضافة Figma Export.
- معاينة المكون المرجعي وتمثيله داخل React، واختبار تنفيذ React الفعلي.
- فحص 5 خصائص: العرض، الارتفاع، اللون، استدارة الزوايا، النص؛ مع إمكانية توسعة المعايير.
- استنتاج الدرجة بناءً على قواعد معلنة وقابلة للاختبار، لا على تقدير نموذج ذكاء اصطناعي.
- مقارنة صور اختيارية فقط إذا توفر مرجع Figma حقيقي مطابق لنطاق الفحص والأبعاد.
- إصدار تقارير وملفات أدلة قابلة للمراجعة والتصدير.

## خارج النطاق في MVP
- سحب تصميمات Figma من الرابط مباشرة من دون آلية تصدير معتمدة.
- مزامنة فورية مع تحديثات Figma cloud.
- إعادة بناء React تلقائيًا من أي ملف Figma أو تحويل React إلى ملف Figma أصلي.
- فحص كل معايير الوصول أو جميع حالات responsive في النسخة الأولى.

## رحلة المستخدم
1. يسلم المصمم نسخة معتمدة من ملفات المصدر.
2. يستورد فريق الفحص البيانات ويتحقق من الحقول المتاحة.
3. يحدد المطور العنصر المقابل في React.
4. يفتح النظام العنصر في المتصفح ويقرأ القياسات الفعلية.
5. يعرض الفرق لكل معيار والدرجة، ومقارنة الصور إن أمكن.
6. يراجع مدير المشروع التقرير والأدلة، ويقر إجراءات التحسين.

## حالات استخدام العرض
- اكتشاف زيادة عرض عنصر من 112px إلى 140px.
- استعادة المطابقة وتوثيق تحسن نتيجة الخصائص من 75% إلى 100% في السيناريو التجريبي.
- مقارنة صورتين متساويتين في الدقة وحساب البكسلات المتغيرة.
- فتح تقرير reg-cli لإظهار الاختلافات بصريًا.

## استراتيجية القياس
نعلن دائمًا 3 مؤشرات منفصلة:
- نسبة مطابقة الخصائص (Property Fidelity).
- تغطية الخصائص التي أمكن التحقق منها (Coverage).
- نسبة التشابه البصري للصورتين عند توفر مرجع حقيقي (Visual Similarity).

لا تُجمع المؤشرات في نسبة واحدة دون اتفاق على نموذج تقييم ومعايرة على بيانات حقيقة.

## شروط نجاح التسليم
- تشغيل React وStorybook وفتح عنصر المقارنة.
- استخراج المرجع من JSON الفعلي وتحديد مصدره ومعرّفه.
- اجتياز اختبارات القياس: اختلاف العرض يظهر خطأ؛ المعالجة تصححه.
- توليد تقرير Playwright بالخصائص المقرؤة من المتصفح.
- عند استلام صورة Figma: تماثل الأبعاد أو توثيق سبب رفض المقارنة.
- ملف HTML قابل للعرض على العميل ويظهر مصدر كل نسبة وحدودها.

## المخاطر والافتراضات
- اختلاف بنية ملف `.fig` عن JSON المنسق؛ يلزم فحص adapter بعينات.
- قيود صلاحيات تثبيت الإضافات في Figma الحكومي؛ بديل: ملف محلي معتمد.
- تعدد الحالات: hover/disabled/mobile؛ لا يغطي MVP كل الحالات.
- اختلاف الخطوط والرندر يؤدي إلى فروق صور حتى مع تطابق بعض خصائص CSS؛ يلزم بيئة ثابتة.
- ضرورة مراجعة التراخيص والأذونات قبل الاستخدام التجاري والإداري.
